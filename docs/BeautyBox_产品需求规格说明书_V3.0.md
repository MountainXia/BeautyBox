## 一、产品定位与不可妥协原则（`已确认`）

1. **核心定位**：私人美妆资产管理与妆容记录 iOS App，服务个人日常护肤彩妆管理、保质期防踩雷、妆容复盘与持妆记录，**不是美妆社区或电商仓库系统**。
2. **核心体验原则——简单为主，精细可选**：
   - 默认以「产品」为中心呈现名称、总拥有件数与主状态；需要管理单瓶生产期、开封日、不同度数的美瞳盒或买入价时，再点开查看与录入单件实物详情。
   - **前端严禁向普通用户暴露「持有实例」「ProductItem」等工程术语**，统一使用自然语言（如「第 1 瓶 / 共 2 盒 / 再添一件」）。
   - 不强迫填完所有专业参数或价格日期才能保存产品。
3. **纯本地、无账号、离线优先**：
   - 首次启动直接进入首页，无注册、无登录、不绑定手机或邮箱，建库不设 `users` / `auth` / `owner_id` / RLS。
   - 核心记录、查询、计算、拍照、相册导入及图片生成分享均 100% 离线可用；个人资料与照片默认只保存在 iPhone App 私有沙盒。
4. **iCloud 与商业化底线**：
   - iCloud 备份默认关闭，开启前明示范围与体积；备份与实时多设备同步概念明确区分。
   - **数据备份、恢复、全量导出（JSON / CSV / 照片 ZIP）对免费用户永久开放**；会员到期绝不锁死、隐藏或删除用户既有记录与照片。
5. **浏览器原型与原生边界**：
   - `prototype/`（`v0.2-task02.1-frozen`）仅作为交互与规则定稿的视觉验证载体，不等于正式 iOS 原生代码已完成。

## 二、全局用户可见交互与业务规则（与 ADR-0002 完全对齐）

### 2.1 Tab 结构与一级导航
V1 固定 5 个一级 Tab（延续原型与 V2.0 原型说明规范）：
1. **首页**：资产概览、临期/过期预警入口、分类分布、最近妆容与快捷新增。
2. **妆匣**：全量产品管理、三级分类筛选（含美瞳周期动态筛选）、多瓶/多盒明细与生命周期切换。
3. **妆容**：妆容日记、多图浏览、四项选填评分、持妆时间线、白名单 PNG 分享图生成。
4. **日常**：单品使用记录（含美瞳实际佩戴打卡）、早晚/周期护肤流程模板及执行打卡、主观肌肤日记。
5. **我的**：会员状态（StoreKit 2）、币种展示设置（`UD-04`）、回收站（`UD-03`）、本地备份/导出、可选 iCloud 备份及隐私说明。

### 2.2 产品命名与录入规则（M1 + M5 + M10）
1. **必填最小门槛**：新建产品仅需确认「品类（分类树末端/直选节点）」与「名称（可自动生成）」即可保存；其余价格、色号、专业参数及日期均选填。
2. **智能命名与保护（`推荐定稿`）**：
   - 当用户选定品牌与分类（及可选色号）且尚未手动改写名称时，名称栏自动建议为 `品牌 + 最细分类名 (+ 色号)`（自动去重空格），避免“Zelens 粉底液”反复重复手打。
   - 用户一旦手动修改名称（置 `is_custom_name = 1`），后续变更品牌/分类/色号**绝不覆盖用户名称**，仅在编辑表单底部提供可选操作「按当前品牌与品类刷新名称」。
3. **规格与拥有数量展示**：
   - 规格栏记录单件净含量/内置片数（数值 + `ml` / `g` / `片` / `支` / `枚` / 其他自定义单位），展示在详情副标题及可选胶囊中，**不混入产品标题**。
   - 列表卡片右上角显示当前未用完总件数（读取所属分类默认单位，如 `2 瓶` / `3 盒` / `1 副`）。
   - 编辑产品快捷减少件数时：仅自动移除无日期、无价格、无妆容关联的空白 `unrecorded` 实物；若待减件包含真实开封记录、价格或妆容引用，**弹窗提示让用户点选具体移除哪一瓶或改为「已用完」**，禁止盲删。

### 2.3 三级分类与特殊品类体验（M4 + M10）
1. **9 大一级分类树**（`UD-01` 待核准种子全表）：
   `彩妆`、`护肤`、`香水香氛`、`身体护理`、`头发洗护`、`美甲护理`、`美妆工具`、`美瞳`（已确认独立）、`其他`；共 **45 个二级分类 + 91 个三级具体产品类型**。
2. **选择器体验**：支持按「一级 → 二级 → 三级」或关键词模糊搜索直达具体产品类型（例如直接搜“唇泥”“气垫”“护手霜”“彩色美瞳镜片”），并对带星号的二级节点（如 `彩色美瞳镜片`、`发膜`、`其他彩妆`）允许两步直接选定保存。
3. **分类专属参数按需折叠展示**：
   - 新建/编辑弹窗首屏保持轻量：品类、品牌、名称、色号（仅彩妆/美甲/有色类默认显露）、主图与基础保有状态；
   - 选择特定分类时按需展示对应折叠区（**全部选填**）：
     - **香水**：浓度（EDP/EDT/Parfum/古龙）、香型、前中后调；
     - **彩妆**：色号、质地、妆效；
     - **护肤/身体/洗护**：适用肤质、主要功效、SPF/PA；
     - **美瞳（`UD-02` 方案）**：产品主档设**更换周期（`日抛/双周抛/月抛/季抛/半年抛/年抛/其他`，作为筛选与展示唯一事实来源）**、基弧 BC、直径 DIA、含水量、花色；单盒实物可分别录入「双眼同度 / 左右眼分度」具体度数（如左 `-2.50`、右 `-3.00`）与盒内片数；
     - **美妆工具**：隐藏刺眼效期警告，提供「清洗周期/备注」替代效期栏（液体洗刷水保留追踪）。

### 2.4 单件生命周期与有效期交互（M2 + M6 + M9）
1. **双正交状态规则**：
   - 用户主动状态仅四态：`未记录`（仅初始默认或通过专门重置入口恢复，**禁止出现在列表快捷状态胶囊中**）、`未开封`、`使用中`、`已用完`。
   - 有效期计算状态独立推导：`正常`、`即将到期`（默认 30 天内）、`已过期`、`无法判断`（工具豁免项显示「无需效期管理」）。
   - `未开封` 与 `已过期` 可并存并显示「未开封 · 已过期」高优先级角标；`已用完` 实物自动沉淀至「已用完记录」筛选 tab 供复盘，**不计入当前持有件数，但计入历史累计消费**。
2. **日期输入、4 层来源与实时校验**：
   - 用户填写开封日期时，**实时校验必须 `开封日期 >= 生产日期`**（均存在时），违规立即行内红字提示并禁止保存。
   - **已确认计算公式**：同时存在未开封截止日（`packaging_exp_date` 优先，或 `生产日期 + 未开封保质期`）与开封后截止日（`开封日期 + PAO`）时，系统自动取 **`min(未开封截止日, 开封日期 + PAO)`**；仅有一侧可用时展示已知侧依据；缺必要原料时**严禁猜测**，标记为「无法判断」。
   - **手动确认日保护**：用户手动填写或点击「采纳推算到期日」后写入 `confirmed_expiry_date`；后续修改生产期/开封日/PAO 时系统立即重算 `computed_expiry_date`，**但绝不静默覆盖 `confirmed_expiry_date`**，而在弹窗内弹出提示条允许用户一键刷新确认日。
   - **美瞳有效期特别交互**：未开封盒仅按 `packaging_exp_date`（外盒灭菌 EXP）判断；标记拆封启用后按 `min(packaging_exp_date, 开封日 + 更换周期天数)` 提示，**严禁在未拆封时凭“日抛/月抛”推测已到期**。
3. **状态转换确认与独立重置**：
   - `使用中 ⇄ 已用完`、`使用中/已用完 → 未开封` 均必须弹出二次确认弹窗；点击「取消」**必须完整放弃本次草稿变动，绝不允许先清除了开封日期却未改状态的半保存行为**。
   - 仅单品详情页底部「更多操作」提供 **`重置为未记录状态`**（红色二次确认）：精准清空 `lifecycle_status`、开封日、用完日、剩余比例、生命周期备注、手动确认到期日与系统推算结果，**完整保留产品主档、价格、购买日期、照片、生产日期、保质期/PAO 原始参数以及历史妆容关联与使用日志**。

### 2.5 妆容记录、持妆与白名单分享（M7 + 隐私规则）
1. **妆容主流程**：
   - 仅「妆容名称」与「妆容日期」必填；「妆容风格」「适用场景」各自提供精选内置胶囊单选或用户手动输入短文本（均可留空），更多关键词用自由标签 `tags` 补充。
   - **四项评分全部选填（`已确认`）**：整体满意度、妆容协调度、色彩表现、持妆表现均允许留空（存 `NULL`），采用 `1～5` 整数星级点选；未填项在个人统计均分中被完全剔除，**绝不当作 0 分拉低平均分**。
   - 支持关联多件真实在手单品并即时固化商品名、品牌、色号、三级分类与规格快照；再次编辑妆容时默认全量保留既有照片与产品列表。
2. **持妆时间线**：支持记录完妆后 2h / 4h / 6h / 8h 或自定义时间点照片、主观脱妆/暗沉/出油等级与感受备注。
3. **安全分享（V1 纯本地白名单图片分享）**：
   - 用户点击「生成分享长图」后进入勾选预览页，仅包含白名单字段（妆容照、名称、日期、风格/场景、自评、产品品牌+名称+色号清单）；
   - **购买价格、获得渠道、剩余比例、私人备注、肌肤日记默认强制屏蔽**。

### 2.6 删除与 7 天回收站机制（M3，`UD-03` 最终确认）
1. 若 `UD-03` 确认采用推荐的 **7 天本地回收站**：
   - 删除单品、整款产品或妆容时进入「我的 → 回收站」保留 7 天，可随时按原 UUID 完整恢复（恢复同名同款不与新产品自动合并）；
   - 到期或手动「彻底删除」时，自动清理沙盒无引用媒体文件，但通过 `ON DELETE SET NULL` 与历史快照继续保住所有关联过的旧妆容展示。
2. 若 `UD-03` 选无回收站，则删除时强制显示完整影响范围二次确认后直接执行安全清理并保留历史快照。

### 2.7 首页累计消费展示与离线日常（M8，`UD-04` + 日常功能）
1. **货币与统计（`已确认`）**：金额以整数最小货币单位 + ISO 4217 `currency_code` 存储，绝对禁止 `Float` 运算、跨币种直接相加与擅自估算汇率。
2. **首页视图（`UD-04` 推荐方案）**：默认弱化一行展示用户在偏好中单选的 1 个主展示币种（默认 `CNY`）历史累计购买总和（含已用完实物）；点击「多币种资产明细」弹窗按各实际消费币种分行精确展示。
3. **日常模块**：支持按日录入单品使用打卡（兼容美瞳佩戴次数与开封累计佩戴天数提示）、自建护肤步骤流程（支持产品快照）与纯主观个人肌肤状态日记，**严禁输出任何医疗诊断或治疗建议**。
