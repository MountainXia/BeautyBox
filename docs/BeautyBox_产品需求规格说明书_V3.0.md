## 1. 产品定位和目标
**妆匣 BeautyBox** 是一款面向个人的 **本地优先、无账号、可自主备份、离线可用** 的 iPhone 原生美妆资产管理与妆容记录应用。它不是美妆社区或云端社交平台，不以用户注册或强制上传个人资料为前提。
- **核心目标**：低门槛连续记录、生命周期与有效期可信不瞎猜、妆容历史真实可追溯、隐私边界由用户完全掌控、数据随时可导出与迁移。

## 2. 核心用户体验原则
1. **「简单为主，精细可选」**——默认看产品与拥有数量，需要时再展开管理每一件的开封、到期、剩余比例与购入价格。
2. **彻底去研发术语**：普通用户界面禁止出现 `Product`、`ProductItem`、`持有实例`、`产品主档`、`数据库`、`CMDB` 等术语，统一使用自然消费用语（产品、拥有数量、第 X 瓶/支/副、我的每件产品、添加一件）。
3. **不强迫录入**：新建产品名称选填、详情可折叠全部跳过、PAO 等非必然字段不强迫填写、不阻断日常使用。
4. **首启直达工作台**：安装后首次打开无需注册/登录即可立即记录。

## 3. 产品信息管理（连续单页与分件可选）
- **连续单页新增流程**：用户在同一个连续页即可完成产品基础信息（分类、品牌、选填名称、规格、照片、私人备注）与拥有数量（默认 1 + 按分类智能推荐的数量单位）填写；下方折叠提供「补充每件详细信息（选填，可跳过）」。
- **名称规则（M1）**：名称可留空；留空时按「品牌 + 具体产品类型（二级分类）+ 色号/款式」自动组合，绝不产生多余分隔符。一旦用户手动填写或编辑自定义名称（`【待用户确认】` 独立标记 `is_custom_name`），后续改品牌/分类/色号绝不自动覆盖用户命名。
- **规格与数量严格分离（M5）**：单件规格（如 `30 ml`、`50 g`、`10 片`）与拥有数量（如 `1 瓶`、`2 支`、`3 盒`）使用独立字段，互不混淆。
- **专属属性按品类按需呈现（M10 · `【待用户确认】`）**：彩妆展示色号/质地/妆效；香水展示浓度/香调；护肤展示肤质/功效；美瞳展示更换周期与度数/基弧/直径；美妆工具提供有效期追踪豁免开关，绝不因分类不同而强迫填写全部字段。

## 4. 产品分类体系（M4 · `【待用户确认】`）
- **一级分类（9 大候选方向）**：`彩妆`、`护肤`、`香水香氛`、`身体护理`、`头发洗护`、`美甲护理`、`美妆工具`、`美瞳`（独立一级分类）、`其他`。
- **二级分类**：按真实使用类型适度细分（详见 `ADR-0002` M4-2 完整分类表），支持 `parent_id` 父子关系与稳定英文编码分离；预留未来用户自定义分类能力，调整分类名称或迁移时不破坏已有产品归属。
- **边界**：色号、香调、香水浓度、容量属于属性，不作为分类扩展。

## 5. `Product` 与 `ProductItem` 的业务区别（M5）
- 底层数据模型严格保持 **`Product`（产品款式）1 : N `ProductItem`（实际拥有单件）** 分离。
- 同款产品不同次购买的价格、币种、购买日期、获得方式、生产日期、未开封保质期、开封日期、PAO、确认到期日、剩余比例与使用状态（以及同款美瞳不同盒的左右眼度数）均在各自单件上独立存储。
- 统计口径：首页与列表分别统计「产品款式数」与「当前持有件数（仅含在手未用完、未移除项）」。

## 6. 产品生命周期（M2 / M9）
- **4 大核心生命周期状态**：
  1. `未记录（unrecorded）`：仅作系统兜底/特殊重置入口态，计入当前拥有数，**不出现在常规快捷状态切换按钮中**；
  2. `未开封（unopened）`：已确认持有尚未开封，剩余比例为 `100%`；
  3. `使用中（in_use）`：已开封使用（须记录开封日期），可记录 `1–100%` 剩余比例；
  4. `已用完（used_up）`：空瓶退出当前持有（记录 `used_up_date` 与使用时长），完整保留历史消费与妆容关联。
- **交互约束与转换保护（M9 · 细则待确认详见 `ADR-0002`）**：
  - 不可选的快捷状态点击需提示明确原因；
  - `使用中 → 已用完`、`已用完 → 使用中`、`使用中 → 未开封`、`未开封 → 使用中` 均设清晰确认交互；
  - 切换为 `未开封` 时清空开封日期、剩余比例重置为 `100%` 并按未开封规则重算有效期；
  - 取消状态确认时不得产生部分保存；
  - 如需将已记录单件重置回 `未记录`，仅通过产品详情专用重置入口并经强二次确认执行（保留产品主档、购买信息、历史妆容与使用日志）。

## 7. 有效期管理与状态独立拆分（M6 / M9）
- **两套状态完全独立**：生命周期状态与有效期状态（`正常`、`即将到期`、`已过期`、`无法判断`）相互正交，例如「未开封」与「已过期」允许并存，卡片先显生命周期态再醒目标注过期/临期风险。
- **双推算与不猜测原则**：
  - 未开封到期 = `生产日期 + 未开封保质期（月）`；
  - 开封后到期 = `开封日期 + PAO（月）`；
  - 缺必要要素不推算、不按品类瞎猜；存在用户确认到期日时最高优先级展示且绝不被系统自动覆盖。
  - 日期逻辑防呆：开封日期与用完日期不得早于生产日期；用完日期不得早于开封日期。
- **「待补充信息」双独立分类（方案 3）**：
  - **待记录使用状态**：仅包含未记录状态的单件（出现日期矛盾标为数据异常）；
  - **有效期信息待完善**：状态已明确（`未开封`、`使用中`）但既无用户确认到期日、又缺少对应计算要素的产品，**必须明确指明具体缺失项**（如 `缺 PAO`、`缺生产日期`、`缺未开封保质期`），仅作为友好提醒，不阻止正常记录与操作；已用完及豁免有效期的工具类不进入此列表。

## 8. 美瞳管理（M4 / M6 / M9 / M10 · `【待用户确认】`）
- **独立一级分类**：设「美瞳」一级分类，二级按更换周期浏览筛选（`日抛 / 月抛 / 半年抛 / 年抛 / 其他周期`）。
- **周期与参数分离**：更换周期结构化存储并与二级分类同步，与盒身规格（如 `10片`）分离；支持选填系列、花纹款式、基弧（BC）、直径（DIA）、含水量及包装类型。
- **单件左右眼不同度数**：左右眼度数允许不同，并支持同款美瞳在不同单件（各盒/各副）记录不同度数。
- **美瞳生命周期分离**：盒身包装有效期（EXP）按未开封/确认到期管理；拆封后的更换周期仅用于佩戴提示参考，不得在缺少依据时盲目推断到期。

## 9. 妆容记录与持妆跟踪（M7 · 细节 `【待用户确认】`）
- **妆容字段**：必填 `名称`、`日期`；可选 `风格`、`场景`（均支持系统精选预设胶囊 + 自定义文本 + 留空，不建复杂外键表）、`耗时`、`多张照片`（区分完成照/局部照）、`Tags`、`私人备注`（默认不分享）。
- **四维可选评分**：`整体满意度`、`妆容协调度`、`色彩表现`、`持妆表现` 四个维度全部保持可选（`1–5` 星），未评分记录不计入均分统计。
- **持妆跟踪**：支持刚完成（0h）及 2/4/6/8 小时或自定义时间节点的照片、带妆分钟数、主观星级与出油/暗沉/脱妆/晕妆/卡粉等状态记录，原生端提供完整 CRUD。
- **日常板块**：包含单品使用日志、早晚/每周/自定义护肤流程模板与执行打卡、主观肌肤日记（多图，附非医疗诊断声明，默认不分享）。

## 10. 产品与妆容关联（历史快照保护）
- 一次妆容或一次护肤流程打卡可关联多个具体单件（`ProductItem`）；同一单件可被多篇妆容引用。
- 关联时自动写入当时产品快照（产品名、品牌、色号、分类）。此后无论原产品改名、状态变更、移入回收站还是彻底删除，历史妆容与流程记录完整保留当时信息。

## 11. 图片管理（隐私与本地沙盒）
- 照片默认仅保存在 iPhone App 私有目录（`Application Support/Media/` + 缩略图），数据库仅存相对路径、MIME、尺寸、字节数与 SHA-256 校验值，严禁 Base64 入库。
- 优先使用系统照片选择器；仅拍照时请求相机权限；仅保存至相册时请求相册写权限。
- 实施基于全库引用计数的孤儿图片清理与删除前明确提示。

## 12. 搜索、筛选与货币展示
- 支持按名称、品牌、分类（含一/二级）、色号、私人备注全文搜索，结合持有状态、待补充（拆分 `待记录使用状态` / `有效期信息待完善`）、临期/过期与历史已用完记录筛选，配合多维排序及列表/网格视图切换。
- **货币体系（M8）**：默认人民币 `CNY`；支持多币种整数最小单位精准存储，绝不跨币种直接相加或汇率换算；历史价格保留原币种；首页默认弱化展示用户选定单币种汇总（可点击查看各币种严格分组明细）。

## 13. 删除与恢复（M3 · 7 天回收站 `【待用户确认】`）
- 整款删除（产品或妆容）进入 7 天回收站（「我的 → 最近删除」统一管理），7 天内可一键恢复；到期启动自动清理或由用户二次确认提前彻底删除。
- 恢复产品严格按原 `UUID` 还原，绝不与后来新建的同款产品覆盖或合并；彻底删除产品时历史妆容与使用日志快照保留，仅解绑外键。

## 14. 数据存储原则与一致性
- 本地数据库锁定为 `SQLite + GRDB`，开启外键约束，采用单向版本化 Migration。
- 状态变更、批量新增、删除与恢复全部在数据库事务内原子执行；取消任何确认弹窗绝不产生部分落库。
- 保存异常诊断日志严格采用白名单脱敏字段，绝不写入价格、私人备注、日记正文或图片。

## 15. 本地离线策略
- 核心资产管理、搜索筛选、统计、妆容与持妆记录、日常日志、本地图片预览、PNG 分享卡生成、JSON/CSV/ZIP 导出在飞行模式或无网络环境下 100% 可用。

## 16. 备份、恢复与数据导出
- 数据导出（JSON、完整字段 CSV、照片 ZIP）与备份/恢复能力**对所有用户永久免费开放**，订阅过期不得锁定、删除或阻断访问/导出已有数据。
- 支持生成包含 `manifest.json`、一致性 `database.sqlite` 快照、`Media/` 与 `checksums.json` 的 `.beautyboxbackup` 备份包；恢复前必须校验格式版本、完整性、磁盘空间并**自动创建本地安全点（Safepoint）**，失败时原子回滚。

## 17. 后续 iCloud 扩展方向（默认关闭）
- iCloud 能力默认关闭；V1 不做 CloudKit 实时多设备同步，仅允许用户主动通过系统文件选择器将 `.beautyboxbackup` 存至 iCloud Drive（由系统级 iCloud Drive 处理跨端传输，如实告知边界，不得虚假宣传为实时同步）。
- 正式原生工程必须将私有数据库、媒体目录及安全点设 `URLResourceValues.isExcludedFromBackup = true`（需 Mac/Xcode 与真机实测），确保未主动操作时不进入系统 iCloud 整机备份。

## 18. V1 范围与暂缓功能
- **纳入 V1（原生正式工程范围）**：上述全部本地资产（含美瞳分类与参数）、生命周期与双有效期、妆容/持妆/日常全闭环 CRUD、免费全量导出、`.beautyboxbackup` 手动备份与 Safepoint 恢复、白名单分享图片、StoreKit 2 配置化订阅。
- **暂缓至后续版本（V1.x / V2）**：用户自定义分类 CRUD 管理界面、自定义通知提醒（`UNUserNotificationCenter`）、妆容步骤拖拽与批量导入、可选的独立匿名 H5 链接分享与好友评分（V1 仅输出架构评估文档，不建表不编码）、CloudKit 实时同步。
- **永久红线（不纳入）**：自有账号/登录注册/`users`/`auth`/`owner_id`/RLS、未授权后台上传、肌肤日记 AI 医疗诊断、跨币种汇率估值、会员过期锁数据。
