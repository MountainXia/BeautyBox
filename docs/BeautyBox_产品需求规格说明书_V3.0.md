## 一、产品定位与不可妥协原则（`已确认`）

1. **核心定位**：私人美妆资产管理与妆容记录 iOS App，服务个人日常护肤彩妆管理、保质期防踩雷、妆容复盘与持妆记录，**不是美妆社区或电商仓库系统**。
2. **核心体验原则——简单为主，精细可选**：
   - 默认以「产品」为中心呈现名称、总拥有件数与主状态；需要管理单瓶生产期、开封日、不同度数的单盒美瞳或买入价时，再点开查看与录入单件实物详情。
   - **前端严禁向普通用户暴露「持有实例」「ProductItem」等工程术语**，统一使用自然语言（如「第 1 瓶 / 共 2 盒 / 再添一件」）。
   - 不强迫填完所有专业参数或价格日期才能保存产品。
3. **纯本地、无账号、离线优先**：
   - 首次启动直接进入首页，无注册、无登录、不绑定手机或邮箱，建库不设 `users` / `auth` / `owner_id` / RLS。
   - 核心记录、查询、计算、拍照、相册导入及图片生成分享均 100% 离线可用；个人资料与照片默认只保存在 iPhone App 私有沙盒。
4. **iCloud 与商业化底线**：
   - iCloud 备份默认关闭，开启前明示范围与体积；备份与实时多设备同步概念明确区分。
   - **数据备份、恢复、全量导出（JSON / CSV / 照片 ZIP）对免费用户永久开放**；会员到期绝不锁死、隐藏或删除用户既有记录与照片。
5. **浏览器原型与原生边界**：
   - `prototype/`（`v0.2-task02.1-frozen`）仅作为交互与规则定稿的视觉验证载体，不等于正式 iOS 原生代码已完成。

## 二、全局用户可见交互与业务规则（与 ADR-0002 V3.1-Frozen 完全对齐）

### 2.1 Tab 结构与一级导航
V1 固定 5 个一级 Tab（延续原型与 V2.0 原型说明规范）：
1. **首页**：资产概览、临期/过期预警入口、分类分布、最近妆容与快捷新增。
2. **妆匣**：全量产品管理、三级分类筛选（含美瞳周期动态筛选）、多瓶/多盒明细与生命周期切换。
3. **妆容**：妆容日记、多图浏览、四项选填评分、持妆时间线、白名单 PNG 分享图生成。
4. **日常**：单品使用记录（含美瞳实际佩戴打卡）、早晚/周期护肤流程模板及执行打卡、主观肌肤日记。
5. **我的**：会员状态（StoreKit 2）、主币种展示偏好与多币种明细（`UD-04`）、7 天回收站（`UD-03`）、本地备份/导出、可选 iCloud 备份及隐私说明。

### 2.2 产品命名与录入规则（M1 + M5 + M10）
1. **必填最小门槛**：新建产品仅需确认「品类（三级末端或可直选二级节点）」与「名称（可自动生成）」即可保存；其余价格、色号、专业参数及日期均选填。
2. **智能命名与保护（`推荐定稿` 冻结生效）**：
   - 当用户选定品牌与分类（及可选色号）且尚未手动改写名称时，名称栏自动建议为 `品牌 + 最细分类名 (+ 色号)`（自动去重空格），避免“Zelens 粉底液”反复重复手打。
   - 用户一旦手动修改名称（置 `is_custom_name = 1`），后续变更品牌/分类/色号**绝不覆盖用户名称**，仅在编辑表单底部提供可选操作「按当前品牌与品类刷新名称」。
3. **规格与拥有数量展示**：
   - 规格栏记录单件净含量/内置片数（数值 + `ml` / `g` / `片` / `支` / `枚` / 其他自定义单位），展示在详情副标题及可选胶囊中，**不混入产品标题**。
   - 列表卡片右上角显示当前未用完总件数（读取所属分类默认单位，如 `2 瓶` / `3 盒` / `1 副`）。
   - 编辑产品快捷减少件数时：仅自动移除无日期、无价格、无妆容关联的空白 `unrecorded` 实物；若待减件包含真实开封记录、价格或妆容引用，**弹窗提示让用户点选具体移除哪一瓶或改为「已用完」**，禁止盲删。

### 2.3 三级分类与特殊品类体验（`已确认 UD-01` + `已确认 UD-02`）
1. **9 大一级分类树（`已确认 UD-01` 正式冻结）**：
   - 包括 `彩妆`、`护肤`、`香水香氛`、`身体护理`、`头发洗护`、`美甲护理`、`美妆工具`、`美瞳`（已确认独立）、`其他`；共 **45 个二级分类 + 93 个三级具体产品类型（总计 147 节点）**。
   - 经过最终校准：拆分了误合并的`护足霜`/`颈霜`、`底油/亮油/封层`（归指甲油）与`指缘油/护甲精华`（归其他美甲护理）、`定型喷雾`/`发蜡/发泥`/`弹力素`、`指甲剪/死皮剪/搓条`/`美甲光疗灯`、`化妆棉/棉签`/`吸油面纸`；规范`爽肤水/保湿水`命名；去除冗余 1 子级子节点。
   - 明确**二级分类直选策略**：9 个一级分类不可直选；12 个无三级子级二级（如`彩色美瞳镜片`、`发膜`、`香膏`、`身体防晒`、`卸甲产品`、`收纳工具`）及部分明确粗粒度便捷二级（如`腮红`、`修容`、`高光`、`香水`、`造型`、`美甲工具`、`化妆刷`、`其他*`）支持直选保存。
2. **选择器体验**：支持按「一级 → 二级 → 三级」逐级展开或关键词模糊搜索直达具体品类（例如直接搜“唇泥”“气垫”“指缘油”“护足霜”）。
3. **分类专属参数按需折叠展示与美瞳单盒粒度（`已确认 UD-02`）**：
   - 首屏保持轻量，仅按分类按需折叠显示选填专业区（**不强制填写**）：
     - **香水**：浓度（EDP/EDT/Parfum/古龙）、香型、前中后调；
     - **彩妆**：色号、质地、妆效；
     - **护肤/身体/洗护**：适用肤质、主要功效、SPF/PA；
     - **美瞳（`已确认 UD-02` 校准模型）**：
       - **同款共用 `Product`**：品牌、系列花色、**更换周期（`replacement_cycle_code`: 日抛/双周抛/月抛/季抛/半年抛/年抛/其他，作为筛选与展示唯一事实来源）**、基弧 BC、直径 DIA、含水量、标称单盒片数；
       - **单盒 `ProductItem` 粒度**：**每 1 条 `ProductItem` 严格代表 1 盒独立包装实物**，仅记录该盒自身的单一**度数（`lens_power`，选填）**与**眼别（`lens_eye_side`：`left` 左眼 / `right` 右眼 / `both` 双眼同度通用 / `unspecified` 未指定）**、购买信息、批号与盒外 `packaging_exp_date`。不同度数、批次、包装**绝不错误合并**；详情页与妆容勾选支持**左右眼成对聚合展示与搭配勾选**，不破坏单盒库存。
     - **美妆工具**：非液体器械与美甲修剪照灯工具设为 `expiry_management_mode = 'optional'`，隐藏刺眼效期警告，提供「清洗/维护备注」；液体洗刷水保留效期追踪。

### 2.4 单件生命周期、历史 `idle` 兼容与有效期交互（M2 + M6 + M9）
1. **双正交状态规则**：
   - 用户主动状态仅四态：`未记录`（仅初始默认或通过专门重置入口恢复，**禁止出现在列表快捷状态胶囊中**）、`未开封`、`使用中`、`已用完`。
   - **历史 `idle` 状态兼容规则**：已废弃 `idle` 枚举，禁止无条件迁为 `in_use`。迁移/导入时，有明确开封日期/PAO/剩余量<100/最近使用或妆容关联证据者迁为 `in_use` 并记录迁移日志；全无上述证据无法判断真实状态者迁为 `unrecorded` 并标待人工核对徽标（保留原 `idle` 迁移审计日志，供用户一键确认未开封或使用中）。
   - 有效期计算状态独立推导：`正常`、`即将到期`（默认 30 天内）、`已过期`、`无法判断`（工具豁免项显示「无需效期管理」）。
   - `未开封` 与 `已过期` 可并存并显示「未开封 · 已过期」高优先级角标；`已用完` 实物自动沉淀至「已用完记录」供复盘，**不计入当前持有件数，但计入历史累计消费**。
2. **日期输入、4 层来源与实时校验**：
   - 用户填写开封日期时，**实时校验必须 `开封日期 >= 生产日期`**（均存在时），违规立即行内红字提示并禁止保存。
   - **已确认计算公式**：同时存在未开封截止日（`packaging_exp_date` 优先，或 `生产日期 + 未开封保质期`）与开封后截止日（`开封日期 + PAO`）时，系统自动取 **`min(未开封截止日, 开封日期 + PAO)`**；缺必要原料时**严禁猜测**，标记为「无法判断」。
   - **手动确认日保护**：用户手动填写或点击「采纳推算到期日」后写入 `confirmed_expiry_date`；后续修改生产期/开封日/PAO 时系统立即重算 `computed_expiry_date`，**但绝不静默覆盖 `confirmed_expiry_date`**，而通过输入指纹在弹窗内提示是否刷新确认日。
   - **美瞳有效期特别交互**：未开封盒仅按 `packaging_exp_date`（外盒灭菌 EXP）判断；标记拆封启用后按 `min(packaging_exp_date, 开封日 + 更换周期天数)` 提示，**严禁在未拆封时凭“日抛/月抛”推测已到期**。
3. **状态转换确认与独立重置**：
   - `使用中 ⇄ 已用完`、`使用中/已用完 → 未开封` 均必须弹出二次确认弹窗；点击「取消」**必须完整放弃本次草稿变动，绝不允许半保存状态**。
   - 仅单品详情页底部「更多操作」提供 **`重置为未记录状态`**（红色二次确认）：精准清空 `lifecycle_status`、开封日、用完日、剩余比例、生命周期备注、手动确认到期日与系统推算结果，**完整保留产品主档、价格、购买日期、照片、生产日期、保质期/PAO 原始参数以及历史妆容关联与使用日志**。

### 2.5 妆容记录、持妆与白名单分享（M7 + 隐私规则）
1. **妆容主流程**：
   - 仅「妆容名称」与「妆容日期」必填；「妆容风格」「适用场景」各自提供精选内置胶囊单选或用户手动输入短文本（均可留空），更多关键词用自由标签 `tags` 补充。
   - **四项评分全部选填（`已确认`）**：整体满意度、妆容协调度、色彩表现、持妆表现均允许留空（存真 `NULL`），采用 `1～5` 整数星级点选；未填项在统计均分中完全剔除，**绝不当作 0 分拉低平均分**。
   - 支持关联多件真实在手单品（包括左右眼成对美瞳盒）并即时固化商品名、品牌、色号、三级分类与单件规格（含美瞳眼别与度数）快照；再次编辑妆容时默认全量保留既有照片与产品列表。
2. **持妆时间线**：支持记录完妆后 2h / 4h / 6h / 8h 或自定义时间点照片、主观脱妆/暗沉/出油等级与感受备注。
3. **安全分享（V1 纯本地白名单图片分享）**：用户点击「生成分享长图」后仅输出勾选白名单字段（妆容照、名称、日期、风格/场景、自评、产品品牌+名称+色号清单）；**购买价格、获得渠道、剩余比例、私人备注、肌肤日记默认强制屏蔽**。

### 2.6 删除与 7 天本地回收站完整规则（`已确认 UD-03`）
1. **删除作用域与父子隔离**：
   - 单删 `ProductItem` 仅移出该单件；整删 `Product` 连同当时尚未被删除的活跃子 `ProductItem` 作为同批次（`trash_scope = 'cascade_with_product'` + `deleted_by_parent_id` + `delete_batch_id`）进入回收站；删 `Look` 仅软隐妆容本身。
   - 回收站仅展示顶层删除入口，**恢复整款产品时只一并恢复因该次删父级被连带移入的子件，绝不把先前用户单独删过的其他单瓶误复活**；恢复时严格**保持原 UUID 且绝不与新建同名产品自动合并**。
2. **7 天期满/提前彻删、快照与照片安全**：
   - 回收站支持随时点击「恢复」或二次高危确认「彻底删除 / 清空回收站」；期满 7 天后自动在单数据库事务内按外键安全顺序彻底清理（先处理 `product_usage_logs` 再删实物，并经 `ON DELETE SET NULL` 完整保留历史妆容产品快照）。
   - **照片文件清理红线**：7 天回收站内禁止删磁盘图片；彻底删除事务提交后，仅当某张图片在 `product_photos`、`look_photos`、`wear_reviews`、`skin_diary_photos` 与 `looks.cover_asset_id` 中的**有效引用总计全部归零**时，方才物理删图。
   - 异常兼容：禁止在父产品永久销毁后单独恢复孤儿实物；若父产品还在回收站，可一键连同父主档仅恢复该指定子件；磁盘丢图不阻塞文字与账目记录恢复。

### 2.7 首页多币种展示与离线日常（`已确认 UD-04` + 日常功能）
1. **货币与统计（`已确认 UD-04`）**：金额以整数最小货币单位 + ISO 4217 `currency_code` 存储，绝对禁止 `Float` 运算、跨币种直接相加与无授权汇率换算。
2. **首页视图**：弱化一行展示用户在偏好中自选的 1 个主展示币种（默认 `CNY`）历史累计购买总和（含已用完实物）；其余币种进入「多币种资产明细」独立分行精确展示，UI 排版可在后续开发期继续细调。
3. **日常模块**：支持按日录入单品使用打卡（兼容美瞳佩戴次数与开封累计佩戴天数提示）、自建护肤步骤流程（支持产品快照）与纯主观个人肌肤状态日记，**严禁输出任何医疗诊断或治疗建议**。
